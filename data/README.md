# Архитектура игровых данных

В этой директории хранятся конфигурации сущностей, баланс, параметры предметов и состояние прогресса.
Все данные строго валидируются через соответствующие JSON-схемы в каталоге `schemas/`.

## Структура каталогов

```
data/
├── schemas/                      # JSON-схемы для строгой типизации
│   ├── player_state.schema.json  # Схема статов игрока, 5-минутного таймера и резисторов
│   ├── enemy.schema.json         # Схема обычных противников (строго 1 вид атаки)
│   ├── boss.schema.json          # Схема боссов (2 атаки у мини-боссов, 3 у финального)
│   ├── world.schema.json         # Схема открытой карты со свободным хабом
│   ├── sprite.schema.json        # Реестр спрайтов (id -> png, кадры, хитбокс, анимации)
│   ├── tile.schema.json          # Определения тайлов (solid / one_way)
│   ├── level.schema.json         # Уровень-сетка из тайлов + спавны игрока и врагов, декор, нитки, объекты, комнаты
│   ├── placeables.schema.json    # Каталог расставляемого: декор с привязкой, нитки, объекты (двери, квестовые предметы)
│   ├── rig.schema.json           # Риг персонажа из частей
│   └── background.schema.json    # Параллакс-фон из слоёв
├── sprites/                      # Реестр спрайтов: связь id -> файлы в assets/sprites/
│   └── sprites.json              # player, enemy_transistoid_*, tile_platform_block
├── tiles/                        # Тайлы уровня
│   └── tiles.json                # platform_block (32x32, solid)
├── rigs/                         # Процедурные риги персонажей (части-слои, pivot-точки)
│   ├── player_rig.json           # Робот-герой: голова, торс, руки, ноги
│   ├── player2_rig.json          # Второй герой: голова с отдельным слоем глаз, торс, руки, ноги
│   ├── spider_rig.json           # Паук-ползун: торс, голова, 4 ноги по 2 фаланги
│   ├── spider_mother_rig.json    # Паучиха-матка: тело и 10 лапок по две части (блок wobbler)
│   ├── worm_rig.json             # Червь-землерой: голова, туловище, хвост (блок segmented)
│   ├── bonzai_boss_rig.json      # Босс-птица Бонзай: 5 слоёв, крылья машут вокруг плеч, круги попадания (блок bird_boss)
│   └── krab_boss_rig.json        # Финальный краб: торс, 4 ноги, клешни на неоновых нитях, шары (блок crab_boss)
├── backgrounds/                  # Параллакс-фоны (слои, скорости, цвет неба)
│   └── bg_textalite.json         # Фон из bg_textalite.aseprite: 8 слоёв
├── objects/                      # Каталог расставляемого в редакторе уровней
│   └── placeables.json           # Декор и его свойства, нитки, объекты: дверь, батарейка, подставка, терминалы
├── levels/                       # Уровни в виде текстовой сетки
│   └── test_level.json           # Тестовая плата 30x8 тайлов
├── player/                       # Начальное состояние робота
│   └── player_initial_state.json # HP, угасание (300с), запчасти (5), резисторы (3)
├── enemies/                      # Конфигурация обычных врагов
│   └── enemies.json              # 9 врагов по 3 на локацию (строго по 1 атаке)
├── bosses/                       # Конфигурация боссов и их атак
│   └── bosses.json               # Готовые боссы: червь-летун (1-я локация), птица Бонзай (2-я), финальный краб (6-я)
└── world/                        # Открытая карта метроидвании
    └── world_layout.json         # Хаб со свободным выбором пути + Сокет ЦП
```

## Связь данных и графики
Графика лежит в [`assets/`](../assets/README.md), данные ссылаются на неё **только по id спрайта**:
`player_initial_state.json` и `enemies.json` -> `sprite_id` / `sprite_variants` -> `sprites/sprites.json` -> PNG.
Проверка ссылок: `python tools/validate_data.py`.

## Редактор уровней (`editor.html`, `LD60Editor.exe`)
Всё, что лежит в `data/levels/*.json`, правится редактором (`src/leveleditor`); формат — тот же JSON, никаких отдельных файлов проекта нет.
Запуск: `npm run editor` (в браузере, dev-сервер) или `npm run editor:exe` → `release/LD60Editor.exe` (двойной клик; ищет проект рядом/на уровень выше или спрашивает папку).
В игре F1 открывает редактор, кнопка «▶ Играть» в редакторе сохраняет и запускает игру на этом уровне (`/?level=<id>&live=1` — свежий файл с диска, без пересборки),
«▶ Отсюда» (Shift+P) — с клетки под курсором (`&spawn=x,y`).

Что умеет редактор (клавиши в скобках):
* **Тайлы** — кисть (B), ластик (E), прямоугольник (U; Shift — рамка), заливка (G), пипетка (I), блоки: выделение (V), копирование Ctrl+C / Ctrl+V.
  **Отражение и поворот**: X — по горизонтали, Y — по вертикали, R — на 90° (для кисти, выбранного предмета или выделенного блока; у блока ещё «⇆ Блок» — зеркало всей раскладки).
  Хранится в `tile_xform`; скосы (`slope`) при этом меняют сторону, коллизия следует за рисунком.
* **Декор** (D) — у каждого спрайта в `placeables.json` свои свойства: `anchor` (стоит на полу / висит под потолком / свободно), `snap` (шаг по x: пиксель / полклетки / середина клетки),
  `layer`, `flip`. Alt при установке — без привязки. Позиция — до пикселя; стрелки двигают на 1 px (Shift — на 8).
* **Нитки** (N) — `level.threads`: `vine` — физичная лиана (звенья по 14 px), цепляется строго по сетке — к нижней грани тайла над курсором (`anchor: ceiling`, `snap: tile` в каталоге; Alt — свободно);
  `sky` — длинная нитка с неба на любой пиксель. Протяжка вниз задаёт длину. **Транзисторы** — обычный декор с привязкой к тайлу (`anchor: floor`, `snap: tile`).
* **Всё расставляется вручную.** Автодекор по зонам (`level.zones`) убран: игра его больше не раскладывает. Старый уровень с `zones` при открытии в редакторе сам превращается в обычные предметы
  (транзисторы — в `decor`, лианы и нитки — в `threads`, раскладка та же, что строила игра) — достаточно сохранить.
* **Удаление и слои.** В каждой вкладке (Декор, Нити, Мобы, Объекты) есть список расставленного: выбрать строкой, удалить 🗑 или «Удалить все». На карте ПКМ перемещает камеру, СКМ удаляет предмет **своей категории** (или стирает тайлы/комнаты) под курсором,
  Ctrl+клик выбирает, Delete удаляет выбранное. Кнопка «👁 Вид» (раздел «Слои») скрывает тайлы, декор за/перед тайлами, нитки, объекты, мобов, старт героя (скрытое не рисуется и не выбирается; «solo» — оставить один слой).
* **Мобы и боссы** (M) — `level.enemies`: клетка спавна, поверхность (пауки выбирают пол/стену/потолок сами), поля по типу (длина червей, верх нитки паучихи).
* **Объекты** (O) — `level.objects` (и `level.terminals` для терминалов брони). **Двери**: каждая дверь ведёт к другой (`to_door`, `to_level` — если на другой уровень), может быть заперта (`requires_item`, `requires_flag`).
  **Квестовые предметы**: `battery` (подбирается касанием, лежит в рюкзаке, сохраняется в localStorage), `battery_stand` (E — вставить предмет и поставить флаг `sets_flag`, например `power_on`, который открывает дверь).
  Логика — `src/world/Objects.ts`, состояние — `src/systems/Quest.ts`. Новые типы добавляются в `placeables.json`.
* **Комнаты** (K) — границы уровней, см. ниже. **Старт героя** (S).

## Комнаты: туман войны, привязка к локациям и «дом» мобов
Комната — набор клеток (`level.rooms[]`: прямоугольник `x, y, width, height` + `mask`, где `#` — клетка комнаты); их закрашивают кистью, областью или заливкой помещения
(клик внутри — заливается всё свободное пространство и кольцо стен вокруг). Комнаты могут перекрываться (проём между ними принадлежит обеим). Старые комнаты без `mask` — просто прямоугольники.
* **Привязка комнат к локациям (`location`)** — поле комнаты `location: 1 | 2 | 3 | 4`:
  * В конструкторе карт (вкладка «Комнаты») у каждой комнаты есть выпадающий список выбора локации (`Лока 1`, `Лока 2` и т.д.).
  * На холсте конструктора при включённых подписях комната сразу отображается с бейджем `[Лока 1] Имя_комнаты`.
  * В статусной строке при наведении курсора на клетки выводится имя комнаты и её локация.
* **Настенный шифр и спавн цифр (`CipherTerminalPuzzle`, `CipherCluesView`)**:
  * В комнатах 1-й локации на стенах спавнятся цифры от **0 до 9**, а под ними — **римские цифры** (`I`, `II`, `III`, `IV`...), указывающие порядковый номер цифры в коде.
  * Шрифт цифр и римских номеров — строго `assets/fonts/uvKits.ttf` (`uvKits`).
  * **Правило фильтрации комнат:** на карте `world_prototype` (прототип карты) и на любых других многокомнатных картах цифры спавнятся **исключительно в тех комнатах, которые привязаны к 1-й локации** (`location: 1`), исключая комнаты боссов и терминала ввода.
  * Карты `LOC1A`..`LOC1E` и `test_level` также полностью поддерживают спавн цифр шифра в своих комнатах.
  * Когда герой подходит к настенной цифре, она заносится в память (`isDiscovered`), вспыхивает искрами и загорается бирюзовым светом.
  * В комнате «Пароль» на терминале ввода игрок нажимает **E** и вводит собранные 4 цифры шифра (поддерживается мышь и клавиатура `0..9`, `Backspace`, `Enter`, `Esc`). При верном коде шлюз разблокируется.
* **Туман войны** — поле уровня `fog` (`true` или `{ "mode": "current" | "explored" }`). Вне комнаты, где стоит герой, мир чёрный (плавно открывается за 0,3 с),
  `explored` оставляет открытыми и уже посещённые. Без `fog` туман выключен. Код: `src/world/Rooms.ts` (`RoomMap`, `Fog`).
* **Дом мобов** — каждый моб и босс привязан к комнате, в которой он стоит (или к `enemies[].room`). Герой в другой комнате — моб его не замечает, не бьёт касанием, червь-босс не охотится,
  матка не плюётся; ходячие, ползающие и летающие мобы не выходят за клетки своей комнаты (`leash` у Critter, Spider, Worm, WormBoss, SpiderMother). Мобы вне комнат не ограничены.

## Полная карта (`world_prototype`)
Одна карта на все локации: справа от хаба — локация 1 (комнаты «Драка», босс-червь), слева — локация 2 (тайл `loc2`, фон `bg_loc2`, босс-орёл `bonzai_boss`), за комнатой орла (левый выход, дверь `door_21`,
открывается победой над орлом) шахта вниз к арене финального краба `room_crab` (фон-шейдер `bg_loc6`, терминал брони у входа). Мобы стоят по комнатам: в локации 1 — пауки, червь-землерой, паучиха;
в локации 2 — электрокрысы, воробьи, стражи; победа над всеми в комнате открывает двери (`WorldProgression`). Победа над крабом ставит флаг `game_won`.
* **Фон комнаты:** поле комнаты `background_id` включает свой фон, когда герой входит в комнату (плавная смена; вне комнат остаётся прежний). Фон «стоит» на низе комнаты героя, поэтому виден на любой высоте карты.
* Тайл другой локации — другой символ легенды (`L` = `loc2`); перерисовывать карту целиком не нужно.

## Фон-шейдер
У фона в `data/backgrounds/*.json` вместо `layers` может быть блок `shader` (`type: "swirl"`, три цвета, `speed`, `spin`, `contrast`, `pixel`) — «закрученная краска» в духе фона Balatro (`src/world/ShaderBackground.ts`,
`pixel` — размер пикселя шейдера в px арта, 0 — гладко; `zoom` — частота пятен, меньше — крупнее и спокойнее). Так сделан `bg_loc6` (фиолетовые тона палитры краба, спокойный и гладкий). Игра выбирает `ShaderBackground` или `ParallaxBackground` по наличию `shader`.

## Урон и здоровье
* **Здоровье врага** — `stats.max_health` в `enemies.json`; у паучков, которых выплёвывает матка, — умножено на их `spawns.scale`.
* **Удар героя** — `combat` в `player_initial_state.json`: урон — случайное целое из `punch_damage` [мин, макс]; с шансом `crit_chance`
  удар критический (урон × `crit_multiplier`). Каждое попадание: цифра урона (шрифт `assets/fonts/uvKits.ttf`; крит — крупная золотая),
  тряска камеры. Когда здоровье кончается, враг выходит из игры и исчезает (эффекты смерти — позже).
* **Падение героя с высоты** (от 7 тайлов; появление на уровне падением не считается) — регдолл (`src/entities/Ragdoll.ts`): таз, шея, голова и стопы падают по физике и сталкиваются
  с тайлами (сквозь стены и пол не проходят), руки-канаты болтаются и тоже упираются в тайлы; улёгшись, герой встаёт «мышцами» из того положения, где лёг.
* На экране нет никакого текста, кроме цифр урона.

## Броня, энергия и терминалы (`data/player/armor.json`, `src/systems/ArmorSystem.ts`)
* **Единственный ресурс — металлолом.** Он падает со всех мобов (сколько — `scrap_drop` по виду моба: паук, критер, червь, матка, босс). Металлолом и броня сохраняются
  в `localStorage` — переживают перезагрузку страницы и переключение уровней клавишами 1–5. Прежние материалы (провода, части диска), модули `standard/wire/disc`, верстак перерождения и
  5-минутный таймер энергоядра убраны (в истории git: `CraftingSystem`, `RebirthUI`, `AgingSystem`).
* **Два вида брони = две модели героя:** модель 1 — прежний герой (первая локация, `player2`), модель 2 — герой второй локации (`player3`). Герой собирается из четырёх частей — голова, туловище, руки, ноги —
  и **каждая часть выбирается независимо** (любое сочетание, например синяя голова на жёлтом теле). Без брони — голое серое шасси (рисунок модели 1, перекрашенный в серое, `entities/armorSkin.ts`).
  Части разных моделей подгоняются друг к другу в `PlayerRig.setArmor`: картинка встаёт точкой привязки (шея, плечо, бедро) в точку привязки рига, у ног берётся длина своей модели, у головы — свои глаза и взгляд,
  руки-канаты пересобираются из картинки выбранной модели. Эффекты брони привязаны к модели (`armor.json`, массивы из 2 значений).
* **Терминал брони** стоит на каждой локации (поле `terminals` в `data/levels/*.json`, спрайт `terminal_loc1` / `terminal_loc2` из `tools/gen_terminals.py`; на loc3 и loc4 пока стиль loc2).
  Герой подходит, над терминалом качается клавиша E; E открывает окно (мир идёт, герой стоит и неуязвим). Для каждой части — кнопки «Шасси», «Модель 1», «Модель 2»: купленное надевается кликом,
  некупленное покупается за металлолом (цена `price`, покупка сразу надевает). **Прежняя надетая часть физически отваливается** (`Debris`: падает, подпрыгивает на тайлах, катится и через `debris_life` с гаснет).
* **Старт в модели:** поле уровня `start_armor` (1 или 2) при входе выдаёт и надевает части этой модели везде, где надето что-то слабее (лучшее не трогается): `test_level` и карта — 1 (прежний герой), `loc2`–`loc4` — 2 (синий герой).
* **Эффекты брони:** *ноги* — двойной прыжок (модель 2 — тройной) и скорость; *руки* — урон ударов ×, **молния каждого третьего удара** (яркая вспышка-звезда, усиленный урон цели и цепные
  разряды на ближайших врагов) и **луч молнии на ПКМ** (вместо броска шестерёнки); *туловище* — здоровье и шанс 8–12%, что урон не засчитается; *голова* — быстрее атака и больше шкала энергии.
* **Единый стандарт молнии** (`effects/Lightning.ts`): все молнии игры строятся одним кодом и светят одним способом. *Форма* — `fractalBolt`: настоящая фрактальная жила (смещение середины:
  крупные дуги и мелкая «шерсть»), поверх — плавный изгиб дугой (молния не ходит по линейке), от жилы отходят ветки под 25–55° вперёд, у веток свои веточки, толщина вдоль жилы гуляет, на конце острие.
  *Рисунок* — `drawBolts`: пиксели арта, жила 1 пиксель, кайма «шахматкой» там, где толсто, редкое внешнее свечение, остаточный тёмный след прошлого кадра (afterglow), мерцание яркости, звёздочки в кисти,
  на отражениях и попаданиях. *Стиль* — `LightningStyle` (цвета палитры): `GOLD` (луч и вспышка героя), `BLUE` (хвост электрокрысы). *Свет* — молния отдаёт освещению мира внешние источники (`Lighting.extraLights`,
  до 8 штук): вдоль луча по источнику на каждые ~44 px (мерцают вместе с молнией), на отражениях и попаданиях сильнее; у вспышки яркий источник на 0.2 с; у хвоста крысы — слабое свечение в покое
  и вспышка в хлёсте. Свет окрашивает тайлы, героя и воздух жёлтым (у хвоста — бирюзово-синим) и даёт блум.
* **Луч молнии:** идёт из кисти по прицелу непрерывно, пока держат ПКМ, тратит энергию (`beam_cost`/с), отражается от стен под нужным углом (до `beam_bounces` раз), бьёт всех на пути (`beam_dps`).
  **Вспышка** каждого третьего удара — звезда из таких же молний и цепные разряды на ближайших врагов.
* **Энергия** — шкала снарядов и луча (жёлтая полоса): копится сама (`energy_regen`/с), без брони головы 100; бросок шестерёнки стоит `gear_cost`, луч — `beam_cost` в секунду. Не хватает — шкала мигает красным.
* **Здоровье героя:** красная полоса; урон наносят электрокрыса (хвост-хлыст сбивает с ног) и касания мобов (`stats.contact_damage` из данных врага, пауза 1 с у каждого; страж
  не кусает), после попадания — неуязвимость `hurt_invuln`. Здоровье кончилось — герой падает регдоллом и возрождается у начала уровня, потеряв `respawn_scrap_loss` металлолома.

## Уровни и отладка
* Переключение уровней в игре: клавиши **1–5** (поле `debug_key` в JSON уровня): 1 — `test_level` (первая локация, в ней стоят все мобы кроме боссов), 2 — `loc2`, 3 — `boss_worm` (арена червя-пожирателя), 4 — `loc2_boss` (арена птицы Бонзай), 5 — `loc6` (финальный краб). `loc3` и `loc4` — пустые заготовки без клавиш.
  4 — `loc4` (3 и 4 — пустые заготовки). Тот же уровень открывается по адресу `/?level=<id>`.
* **Тайлы — явные.** Каждый кадр каждого листа (`textalite` — 10 кадров, платформа — край/середина/край/заливка и т.д.) — отдельный тайл в `data/tiles/tiles.json` (`sprite_id` + `frame`), в палитре редактора они разложены по группам.
  Автоматики нет: игра не выбирает кадр по соседям (верхний слой/толща/края платформы) — какой тайл поставлен в клетку, такой и рисуется. Старые «умные» тайлы `platform_block` и `textalite` в уровнях уже развёрнуты
  в явные (`tools/migrate_tiles.mjs` — одноразовая миграция).

## Герой и мобы второй локации
* **Герой не зависит от уровня:** собирается из частей двух моделей — прежний герой (`player2`, `player2_rig`) и синий человечек второй локации (`player3`, `player3_rig`, слои `assets/source/player/loc2_char.aseprite`); см. «Броня, энергия и терминалы». Прежнее поле уровня `hero` убрано.
* **Бросок** (ПКМ, спец-атака): рука поднимается вверх впереди (нормальным поворотом, а не заводится за спину) с шестерёнкой в кисти, затем рывок над головой вперёд вдоль прицела, и в момент отпускания шестерёнка
  вылетает из кисти (`Player.startThrow` → `PlayerRig` поза `throwing` → `onThrowRelease` → `ProjectileSystem`). ЛКМ — удар кулаком, как раньше.
* **Мобы:** электрокрыса, воробей, страж (ward) — небольшие существа из слоёв с процедурной анимацией (`src/entities/Critter.ts`, блок `critter`
  в `data/rigs/*_rig.json`: повадка `walker` / `hopper` / `flyer` / `watcher`, детали с анимациями `step`, `swing`, `wag`, `bob`, `bounce`, `flap`,
  `squash`, `track`, `peck`). Детали плавно догоняют целевую позу (пружина), разворот — плавное сжатие рисунка, воробей на прыжке вытягивается
  и на приземлении сплющивается, ноги вжимаются в тело (анимация `tuck`) и раскрываются на спуске; голова воробья не поворачивается и не уходит вверх от рисунка — только приседает вниз (`bounce` с отрицательным `amp` + `sink` — идёт за туловищем только вниз), так не отрывается от тела.
  Все бьются кулаком (здоровье — `stats.max_health`); воробей и страж никого не трогают.
  **Хвост электрокрысы** — процедурная молния (`src/effects/LightningTail.ts`, блок `critter.tail` рига; спрайт хвоста убран): острая зазубренная молния
  пикселями арта, сужающаяся к кончику, цвета — рампа cobalt палитры проекта. Крыса бродит по полу; когда хвост «отдохнул» (`tail.whip.cooldown`) и герой
  в зоне видимости, она подбегает (быстрее), замахивается (хвост вздымается дугой над спиной, потрескивает), хлещет по земле (хвост проносится дугой вперёд и вниз, корень уже бьёт вниз, а кончик догоняет — петля, как у кнута; хвост ложится на пол, на щелчке — искры)
  и сбивает героя с ног, если задел ноги (прыжком хлыст можно перепрыгнуть): `Player.knockdown` — герой падает регдолл-физикой, как с высоты, затем встаёт сам (повторно не
  чаще чем раз в ~3 с). В паузе между хлёстами крыса держится от героя на расстоянии.

## Правила боевой системы (Количество атак)
* **Обычные противники:** строго **1 вид атаки** (по 3 моба на каждую из 3 основных локаций):
  * **Материнская плата**:
    * `Транзистоид`: «Искровой прыжок» (12 ур, кд 2.2с).
    * `Свайр`: «Удар лапкой» (14 ур, кд 1.5с).
    * `Шинный дрон`: «Медленный энергозаряд» (10 ур, кд 3.0с).
  * **Блок питания**:
    * `Дроссель-червь`: «Удар пружинного растяжения» (16 ур, кд 2.0с).
    * `Электролитный плевун`: «Плевок электролита» (15 ур, кд 2.8с).
    * `Летающий трансформатор`: «Четверной залп» (18 ур, кд 3.5с).
  * **Жёсткий диск**:
    * `Бит-флиппер`: «Магнитная инверсия (Притяжение/Отталкивание)» (14 ур, кд 2.5с).
    * `Летающая игла`: «Пикирующий укол» (22 ур, кд 2.2с).
    * `Чип`: «Рикошетящий сгусток данных» (14 ур, кд 3.0с).
* **Боссы:** в игре только готовые (недоделанные боссы с «заглушечными» спрайтами окружения убраны из `enemies.json`, `bosses.json` и карты мира). Новый босс добавляется вместе с рисунком, ригом и кодом.
  * **Червь-летун** `worm_boss` *(1-я локация)* — `src/entities/WormBoss.ts`, риг `worm_boss_rig`: летает сквозь тайлы, части с отдельным здоровьем.
  * **Бонзай** `bonzai_boss` *(2-я локация, арена `loc2_boss`, клавиша 5)* — `src/entities/BirdBoss.ts`, риг `bonzai_boss_rig`, рисунок `assets/source/bosses/boss_bonzai.aseprite`, птички `boss_bonzai_bird.aseprite`.
    Одна полоса здоровья (600), на «уровень выше» червя. Цикл боя: **пике** (замирает и отводит крылья назад, потом проносится по прямой сквозь героя, как оса в Террарии; сбивает с ног, в стену — отскок и тряска) и **стая птичек**
    (замирает и выпускает веер птичек `BossBird`, они гонятся за героем и клюют, бьются с одного удара); после серии атак **садится на пол и призывает двух обитателей локации** (`summons` в `enemies.json`: электрокрыса, воробей),
    сидит ~7 с — **только тогда её бьют в полную силу** (в воздухе удар гасится ×0.35, по крыльям ещё мягче; метод `damageScale` у `PartDamageable`). Ниже 50% здоровья звереет: быстрее пролёты, больше птичек, длиннее серия.
    Тюнинг — константы в начале `BirdBoss.ts`.
  * **Краб-Ядро** `krab_boss` *(финальный босс, уровень `loc6`, клавиша 6)* — `src/entities/CrabBoss.ts`, риг `krab_boss_rig`, рисунок `assets/source/bosses/krab.aseprite` (холст 400x300, в игре вдвое меньше:
    `tools/downscale_pixelart.py` делит слои без новых цветов → `assets/sprites/bosses/krab_layers`). Здоровье 1400, одна полоса (вверху экрана); тело бьётся в полную силу, клешни — на 20%.
    **Клешни — отдельные тела на неоновых нитях** (`src/effects/NeonThread.ts`, рампа virus): подвешены к плечам, пружинят к цели, нить провисает, пока слабо натянута, и трепещет в ударе; свет — `CrabBoss.lights()`.
    Нити начинаются с самого крайнего пикселя торса (`shoulders` в риге). Прыжки идут по дуге **без столкновений с тайлами** и заканчиваются точно на поверхности цели (пол под героем или уступ).
    Три атаки: (1) **прыжок** на героя — ударная волна по полу при приземлении (перепрыгнуть можно) и удары клешнями по очереди туда, где стоит герой (место отмечено бегущей полоской на полу);
    каждый удар — тряска, вспышка, расходящиеся неоновые кольца, трещины и обломки плит (`impactFx`);
    (2) **шары** — клешни лепят по золотому шару (`CrabOrb`) и швыряют в стороны, **три пары подряд** (в ярости четыре); шары катятся по полу, отскакивают от стен и ломаются, столкнувшись друг с другом (кулак разбивает любой);
    (3) **платформа** — запрыгивает на ближайший к герою широкий уступ в 3–6 клетках над полом (ищется сам, `findLedges`), встаёт у края и **швыряет мобов вниз** из-под края платформы: крыс, воробьёв и пауков (`summons` в `enemies.json`, швыряет `Critter.toss` / `Spider.launch`).
    Ниже 50% здоровья звереет (быстрее, больше прыжков, мобов и шаров). Камера держит верх босса в кадре (`GameApp.updateCamera`). Тюнинг — константы в начале `CrabBoss.ts`.

## Модель перемещения (Open Hub-and-Spoke)
Никаких искусственных линейных ограничений или запертых дверей между 3 основными узлами железа:
1. Игрок имеет свободный доступ из **Центрального Хаба (`loc_central_hub`)** в любую из трёх сторон в любом порядке:
   * **Материнская плата** (через дорожки шины данных).
   * **Блок питания** (через жгут проводов 24-pin).
   * **Жёсткий диск** (через SATA-кабель-канал).
2. Победив любого мини-босса, игрок забирает резистор и может в любой момент вернуться в Центральный хаб, вставить его в панель и отправиться в следующую локацию.
3. Единственная закрытая дверь — **Сокет ЦП (`loc_cpu`)**, гермошлюз которого открывается только после калибровки всех 3 резисторов на щитке хаба.
